## 2 技术基线

- 引擎：Godot 4.7.2 Standard Windows x86_64；以实际 `--version` 记录完整构建标识。

Godot Resource 用于内容数据，加载对象可能被共享；运行状态必须另存，不能依赖“加载一次就得到独立对象”的假设。参考 [Godot 4.7 Resource 文档](https://docs.godotengine.org/en/4.7/tutorials/scripting/resources.html)。

## 5 地图的三维扩展契约

### 5.1 世界定位

世界地址由 `dimension_id + chunk_x + chunk_y + chunk_z` 构成，分块内位置使用局部米制坐标。世界种子与存档世界 ID 另存。首版只有 `world.main` 维度，空岛与地下属于同一维度中的不同三维位置；后续确需独立世界时再增加维度定义。

计划的加载分块为 64 m 立方体；地区规划单元暂定 512 m 水平边长，允许多个垂直层和任意三维包围体。尺寸为可验证的配置，不能由各生成器各自假定。

公共输出是 `ChunkDescriptor`，包含表面或结构数据、碰撞输入、放置清单、语义锚点与稳定实体 ID。不能将世界公共接口定义成单层高度图，也不强迫所有生成器存储稠密体素。

### 5.2 群系与地形提供者分离

`BiomeDefinition` 描述分布条件、风格、内容池、规则参数和生成器引用；`GenerationProvider` 负责具体几何生成。类似风格的城市可以共享城市生成器，空岛和地下可以分别增加生成器。

计划接口，具体语法在 M3 实现时以 Godot 4.7 API 为准：

```text
plan_region(context, region_key) -> RegionPlan
describe_chunk(context, chunk_key, intersecting_plans) -> ChunkDescriptor
validate_region(region_plan) -> ValidationResult
```

`context` 为只读快照，包含种子、版本、单位、内容索引与参数，不包含活动节点。`RegionPlan` 含三维 bounds、结构归属、道路或通道连接口与生效层。一个分块可以接收多个互不冲突或已定义合成规则的结构贡献。

地表提供者可内部使用高度场，空岛提供者输出带下表面的封闭体或组合网格，地下提供者输出洞室、通道和入口。它们均通过相同的描述和加载接口进入世界。

### 5.3 组合与边界

- 先规划区域与跨区连接，再把几何分配到分块；不让每块独立随机道路。
- 结构有唯一 owner，跨块引用 owner 计划，避免重复生成桥梁和奖励实体。
- 群系有优先级、容许高度、三维分布和过渡规则。相交实体按显式规则合成或拒绝，不靠加载先后覆盖。
- 地表、地下入口和空岛之间用语义连接口对接，校验净空、坡度或空间距离。地下入口不得被地表提供者再次填满。
- 网格接缝与碰撞边界分别检查。不同尺寸细节不能在交界处形成不可见碰撞面。
- 新群系允许引用不同任务和商店内容池，不允许直接修改飞行控制逻辑。

### 5.4 确定性和内容升级

使用固定版本的种子派生函数，输入世界种子、地区键、提供者 ID 和阶段标识；不依赖遍历顺序、线程完成顺序或未经版本固定的通用 `hash()`。候选内容排序后选择，为装饰使用独立随机流，添加装饰不改变道路和任务 ID。

每份世界存档固定生成器版本、内容包版本与具体清单摘要。新增群系默认用于新世界；向旧世界开放必须定义未访问地区的迁移规则和边界策略。仅检查“地区未访问”不能保证边界连续，不自动将新算法应用到旧世界。

### 5.5 扩展性需要验证

新增第二种城市风格时，仅新增资源、内容清单和素材；新增全新空岛几何时，可以新增提供者并登记，但不改加载器、飞行器或任务状态机。M3 必须用空岛和地下夹具穿越入口、上表面与下表面，并跨越垂直分块边界，不能只建立空接口就宣称支持三维世界。

### 5.6 交互地图与导航

地点分为传送点、商店、任务和普通地点。地图点击仅选择目的地并开启导航；只有显式标记为传送点的条目可通过独立按钮传送，执行入口再次校验类型。商店和任务必须自行飞抵，不能把其平台作为快捷部署按钮。

地图支持平移、缩放、全图和无人机定位。选中高亮在关闭地图后保留，飞行画面显示目标或航点高亮、屏幕外/身后方向箭头、距离及高度差；第一和第三人称共用。导航使用三维世界坐标，原点平移不能移动目的地；同一 X/Z 的不同高度不能误判到达。

当前航线为参考连线；地下按数据声明的入口、井底和内部范围组织进出航点，不包含全局碰撞避障或自动驾驶。传送后清空运动、等待碰撞就绪并保持暂停。旧存档的非传送部署位置从最近正式传送点恢复。导航选择与航点进度是运行状态，不写入共享地点定义或奖励事务。

### 5.7 世界内容与视觉细化（本轮）

用户明确暂缓飞行录像与回放，优先城市/群系扩展、缩小粗大地形体块、提高地形与建筑材质辨识度。本轮已实现连续细网格地形、工业/园区建筑差异、砖石旧城与林地山谷，以及按表面类别区分纹理、光泽和颜色；自动与窗口证据见VALIDATION.md，用户体验待验收。保持 Godot 原生能力、三维公共几何接口与既有任务坐标；不引入外部原生依赖。

地形算法更新须提升世界版本。旧世界继续按原版本生成；升级入口明确备份原档、保留装备/设置/任务和信用点、重建地形并回到安全起降点，用户主动升级后才采用新规则。连续边界、地下入口、碰撞和正常窗口帧时间须重新验证，不能仅以增加细节数量宣称优化完成。

## 6 无人机与配件系统

### 6.0 用户的实际输入设备

用户已反馈富斯 i6x 与 FrSky 遥控器可连接飞行。界面使用通用遥控器名称；游戏读取 USB 转换后由 Godot 暴露的控制器数据，不直接实现遥控器无线协议，不按品牌名假定通道顺序或开关数量。

校准一次采集四根轴的行程，三根姿态轴回中、非回中油门最低后完成采集，记录端点与中点。根据唯一位于端点的轴定位油门，其余轴初次按 USB 索引分配，已有姿态分配优先沿用；用户通过下拉框核对横滚、俯仰、偏航，并用独立开关切换每个通道正反。四轴独立处理，不把横滚和俯仰合成普通角色移动的圆形归一化输入。非回中油门按全行程映射到 0 至 1，不套用回中手柄的油门逻辑。

辅助通道逐个采集，读取未占用的 USB 轴或按钮，识别后选择二档、三档、可回弹二档或连续旋钮 / 滑杆类型。三档支持轴、两个按钮加中位、三个互斥按钮。设置页提供命名、正反、实时档位与移除，并按档位绑定暂停/恢复、重置、视角、拍照、菜单与交互动作，存入同一命名配置。回弹通道随按下与松开变化，不转成软件锁存。持续停留不重复触发；交互动作支持按住。连续旋钮的绑定按低、中、高三个区间处理并使用回差避免抖动。

通道标签与实际 USB 轴号一致，轴 n 即通道 n，方便同页预览比对。重置区分「回到部署点」（R 键，完整姿态与速度归零）与「原地重置姿态」（保留位置和水平朝向，横滚/俯仰与两种速度归零），均可独立绑定，保留原暂停状态。

配置按设备标识与用户配置名保存，不能认为同一通用 USB GUID 总对应同一台遥控器。加密狗不暴露开关时，保留键盘动作入口。飞行只区分暂停与运行，取消电机解锁步骤及最低油门门槛。P / 空格或绑定动作恢复后即可按当前摇杆飞行。失焦或断开输入时暂停；重新接入后要求显式恢复，菜单和失焦期间不执行辅助动作，激活配置、关闭菜单和窗口回到前台时先同步当前档位，不能因开关原本处于某档而自动恢复。设备识别和映射先用 Godot 4.7 实测；若失败，保留枚举结果并检查映射，不凭 4.3 的表现下结论。参考 [Godot 控制器文档](https://docs.godotengine.org/en/4.7/tutorials/inputs/controllers_gamepads_joysticks.html)。

### 6.1 定义、配置和计算结果分离

- `PartDefinition`：配件不可变规格、允许调节范围、兼容标识、视觉与许可引用。
- `DronePresetDefinition`：套机推荐配置、默认调参和获取包，不是另一套独立飞行代码。
- `DroneBuild`：玩家选择的配件 ID 与每个实例的调参值，可保存多份。
- `ResolvedDroneSpec`：装配校验成功后生成的质量、惯性、受力位置、阻力、动力映射和安全边界。
- `FlightProfile`：摇杆 Rates、Expo、相机与辅助偏好。与硬件解锁分离，基本操控偏好无需任务解锁。

套机和自由装配必须共用装配管线，UI 显示值与物理值都从 `ResolvedDroneSpec` 读取。不能让套机描述展示一套数值、实际控制器又使用另一套常量。

### 6.2 第一原型的安装规则

首版固定四旋翼。机架包含四个受力点；`motor_set` 与 `propeller_set` 表示四个匹配组件的安装选择，包含正确旋向的两对桨叶。暂不做四个异构电机或不同桨叶的自由混搭。

校验顺序：内容存在与已取得权限、机架拓扑、安装孔与轴径、桨径和旋转净空、对应动力映射、质量与惯性有效、调参范围、推力余量。错误返回可读原因，并保留上一个有效配置；失败装配不能把飞行器推进到半更新状态。

### 6.3 有限调参与物理影响

每个配件拥有自己的 `TuningSpec`，给出单位、默认值、最小最大值、步长、作用路径。UI 与存档加载共同验证范围，不能仅限制滑块。拒绝 NaN、无穷、未知参数或不存在的配件；历史配置的范围变化采用显式迁移并给出提示。

初始建议：机架开放相机安装角或小范围设备安装位置；电机开放约 ±5% 的响应整定及有限推力上限；桨叶开放约 ±2% 的气动校准。桨距、桨径、叶片数、真实质量等硬件规格保持定义值，通过换配件改变。气动校准必须标为仿真整定，不能声称真实定桨距桨叶能任意调桨距。

这些是游戏初始调参边界，不是实测硬件数据。每项参数都要有可观察影响，并保持套机差异。部分参数属于配置便利而非性能升级，不能把所有配件设计成单一数值越大越好。

### 6.4 受力与动力映射

质量来自机架、四个电机、四片桨叶与固定系统质量。系统质量是不可购买、不可调节的整机背景参数，不建立电池对象或电量状态。惯性按简化几何和组件位置计算，首版可采用可验证的近似模型。

电机与桨叶不是互不相关的倍率。`PropulsionMap` 关联电机与桨叶组，在固定参考供能条件下定义控制量到推力、反扭矩和响应的映射。无映射的组合不能静默套用默认值。新配件可只支持一部分合理组合。

供能视为恒定背景条件。没有耗电、容量、充电、热量衰减或需要定期回站的能量机制；推力仍受机型、动力映射和空气阻力约束。

### 6.5 飞行核心

机体坐标约定为机头朝本地 -Z、上方为 +Y、右侧为 +X。输入正值分别表示右压横滚、向前俯仰、向右偏航，在唯一的输入到机体映射处完成符号转换，并通过基础动作验收；不得在不同控制阶段散落补偿负号。内部角速度用 rad/s，界面明确标注 deg/s，换算只在边界执行。

Acro 输入转为目标角速度，经控制器和混控器转为四电机指令，再在受力点施加推力及反扭矩。保持坐标、旋向与单位显式。松杆不自动回正；对接辅助单独启用，不能悄悄修改自由飞行手感。

用 RigidBody3D 的物理接口更新，不在每个渲染帧强改刚体位置模拟正常飞行。高速碰撞、地面接触、重置与暂停/恢复均有独立测试。参考 [RigidBody3D](https://docs.godotengine.org/en/4.7/classes/class_rigidbody3d.html)。

装备台暂停物理后才能应用新装配，更新整机参数与控制器状态后恢复飞行。首版不提供运行中即时换桨。玩家不再操作电机锁定/解锁；装备解锁仅表示取得装备权限。

暂停保存机体的线速度和角速度，恢复后续接原来的运动；反复暂停或打开菜单不得用冻结后的零值覆盖快照。只有显式回部署点或原地重置姿态才清空速度。暂停时允许使用附近商店和维修终端，冻结状态视为稳定停留；菜单内仍停止飞行动作与世界运动。

操控曲线按横滚、俯仰、偏航分别设置角速度上限（30～1200 °/s）和 Expo（0～0.95），曲线预览与控制器共用计算。新配置不再硬编码偏航比例，旧配置的偏航 70% 规则仅在转换为三轴值时保留。高级环境提供重力（0～30 m/s²）、空气阻力倍率和转动阻力倍率（各 0～5），默认 9.81、1、1。它们是本地玩家飞行偏好，和不可变配件资源分离；设置需范围与有限数值校验、持久保存、可恢复默认，预览或取消不能改变当前仿真。

## 7 获取渠道与探索进度

本轮已将维修与首个浮岛拍摄委托统一为资源化任务，提供任务面板、领取/追踪、地图导航、进度持久化与原子奖励。维修保留直接按住 E 的入口；拍摄无倒计时，要求相机距离、取景角度及无遮挡条件，照片与元数据保存成功后才提交完成。旧维修进度沿用稳定设施事务，不重复发奖。实际接口见 IMPLEMENTATION.md，自动、窗口及用户可玩性验收记录见 VALIDATION.md，尚不包含回放、任务编辑器或完整艺术评分。

目录中的存在、已解锁可获得、玩家已取得、当前装备是不同状态。定义与获取方式由数据组合，支持初始赠送、城市任务奖励、商店、探索发现和后续社区事件。

`AcquisitionRule` 用显式条件组表示 AND 与 OR，引用任务、城市或群系标签、商店和目标配件 ID；任务系统不认识具体零件名。首版只实现初始、任务、商店三种渠道，其余作为后续规则类型。

套机奖励是原子取得包：授予套机蓝图及必需组件使用权。不能只解锁一个仍因缺件无法使用的套机。初始赠送的重复配件不重复累加。

原型采用永久使用权，不模拟消耗库存和每片桨叶的数量。商店使用游戏内信用点；购买校验条件、余额、已有权利和兼容提示，完成一笔后保存完整进度。任务奖励与购买均使用唯一事务标识，重启、重复触发或打开页面不能多次发奖或扣款。

同一项装备允许多个获取渠道；未到达某个具体随机城市不能永久失去关键装备。城市任务按群系或城市类型与任务标签匹配，稳定城市 ID 用于记录完成情况。自由飞行的基础套机和操控设置始终可用，调试全解锁单独存档，不污染正常进度。

## 8 加载、碰撞与坐标

分块状态：请求、数据就绪、几何准备、碰撞就绪、激活、卸载。数据生成可以后台进行；活动场景树、资源提交和碰撞激活按线程安全接口处理。

以速度和位置规划前向预取，保留周围碰撞，不只依赖视野。首版用有限区域校验，再测试 40 m/s、快速掉头和垂直俯冲；没有就绪的区域不能直接进入。分块异步结果带 generation token，卸载后到达的旧结果丢弃。

原点平移在可控物理边界进行，同步机体、目标、相机、音源和调试对象；全局实体键与种子不变，速度与朝向保持。P1 在开发场景测试原点平移，不要求在首张地图上频繁触发。

远景只保留视觉，远处事件存状态而不持续物理模拟。逐块合并表面网格和重复实例，不按方块创建 Node。空间预算和创建队列可在调试 UI 查看。

## 9 存档与内容兼容

存档至少包含：格式版本、世界种子、生成器与内容清单版本、玩家位置和维度、发现记录、设施状态、任务状态、已解锁与已取得 ID、信用点、已处理奖励事务、套机配置与调参、输入偏好。

内置 Resource 保持只读，用户状态保存在 `user://` 下的数据文件。存档只存稳定 ID 和玩家数据，不把运行节点或任意可执行脚本序列化进存档。采用临时写入、完整校验、替换与上一份备份。

删除或缺失内容时保留原始 ID 和配置快照，提示缺失项，回退至安全初始机；不能静默替换成更强的配件、清空玩家解锁或覆盖无法迁移的旧存档。记录迁移报告。

## 10 工作流与验收

每轮读取当前里程碑，选择一个可运行任务，确认影响接口，完成实现和必要验证，更新进度与日志。单轮不为了“架构完整”提前实现后续所有系统。

优先提供可独立打开的飞行试验、装备验证、群系生成预览、交互和存档场景。工具要能输出种子、版本、活跃块、碰撞状态、整机计算结果和任务事务 ID。

自动验证重点：确定性、跨块连接、三维几何、内容校验、调参边界、动力匹配、取得权限、奖励幂等与存档恢复。正常运行重点：真实输入、Acro 手感、看清障碍、装备差异与加载帧时间。headless 与窗口验证分别记录。

P1 性能目标为本机 1080p 简化画面稳定 60 fps，固定路线连续飞行 15 分钟无加载空洞和持续内存增长。该目标未实测，日志必须列种子、构建、硬件、画面与后台条件，不用瞬间高帧率代替标准路线。
