# 原型里程碑与进度

更新时间 2026-10-21。以下是执行顺序，不是工期承诺；新功能按验收推进，已写代码和已通过验收分别记录。

## 当前状态

- 已完成：官方版本核查、本机环境检查、开发入口与内容契约。
- 当前尚未开始：Godot 游戏工程、飞行控制、群系生成、装备与任务实现。
- 下一步：用户提供 Godot 4.7.2 Standard 的实际目录后，开始 M0。控制设备已确认为富斯 i6x 加 USB 加密狗，轴与开关映射在 M1 实测。
- 本机现有引擎为 4.3，未发现 4.7.2；不使用旧版结果代替新基线验证。
- 开发文档是后续工作的依据，世界主题与初始数值属于可调整默认值。

## M0 工程与验证入口

目标：得到能打开、导入、运行和检查的最小工程。

- [ ] 检查实际 Godot 4.7.2 版本和启动方式。
- [ ] 创建 `game/project.godot`、最小主场景、输入动作、基础材质和调试 UI。
- [ ] 建立可配置的本地引擎路径，不向通用代码写入个人绝对路径。
- [ ] 初始化本地 Git 与 `.gitignore`，保留文档；不推送远程。
- [ ] 为已有 `output/` 与 `tmp/` 设置合适的版本管理范围，不把预览与构建垃圾加入工程。
- [ ] 加入最小无外部依赖的测试入口和内容校验入口，名称与文档对齐。
- [ ] 记录 headless 导入与正常窗口运行结果，确认键盘调试输入可用。

交付：可运行的空白灰盒、启动说明、真实环境记录。

## M1 首个可飞灰盒

目标：提前交付能自由飞行的版本，供用户评价操控。

- [ ] 一款临时基准四旋翼，使用之后可替换的 ResolvedDroneSpec 输入，避免将具体配件写进控制器。
- [ ] Acro、解锁与重置；受力、阻力、重力、相机角度和可配置 Rates。
- [ ] 富斯 i6x 加 USB 加密狗读取与逐轴校准；不足的开关通道使用键盘绑定，其他设备可建立独立配置。
- [ ] 验证非回中油门、各轴独立最大行程、失焦暂停、拔插与显式恢复；未接设备时明确使用键盘调试模式。
- [ ] 平台、立柱和桥洞，包含地面接触与高速碰撞检查。
- [ ] 显示姿态、速度、实际物理步长、受力与帧时间。
- [ ] 没有电池与续航状态，连续飞行无需补给。

验收：能起飞、悬停、绕飞、落台、俯冲和重置；无输入时的姿态行为符合 Acro；精细手感的实际设备验证单独记录。

## M2 套机与有限调参

目标：以正式资源管线替换 M1 临时规格，证明新增配件不改飞行核心。

- [ ] 自定义定义类、内容清单、注册表与引用校验。
- [ ] 两机架、两电机组、三桨叶组、两套机和三条动力映射。
- [ ] 装配校验、质量惯性与受力位置计算，产生唯一 ResolvedDroneSpec。
- [ ] 装备台显示兼容性、性能取向、限定调参与错误原因。
- [ ] 校验范围边界、错步长、NaN/无穷、缺映射与不可安装组合。
- [ ] 套机和自由装配共用计算；落地且电机锁定时应用配置。
- [ ] 两机型与两款 5 寸桨叶在固定试飞条件下呈现可观察差异。

验收：新增测试配件与对应映射后，控制器文件无需修改；有限调参能保存，不改变共享资源。暂以明确的调试权限访问内容，正常获取在 M4 接入。

## M3 群系与三维分块

目标：得到约 512 × 512 m 的连续样本，并用夹具验证未来城市、空岛和地下的接入。

- [ ] 三维块键、地区计划、ChunkDescriptor 与生成提供者注册。
- [ ] 两个地表群系资源，支持同一城市提供者的不同风格参数。
- [ ] 桥、平台、道路与峡谷；跨块结构唯一归属。
- [ ] 按需加载、碰撞就绪门槛、卸载、过期结果丢弃与调试显示。
- [ ] 同一种子不同加载顺序得到相同语义结果，含负坐标与地区边界。
- [ ] 空岛夹具测试顶面、侧面、下表面与垂直块边界。
- [ ] 地下夹具测试入口、洞室与地表合成，不被地形填满。
- [ ] 原点平移测试保持机体姿态、速度、ID 和生成结果不变。

验收：新增城市风格只改内容资源；空岛和地下提供者复用加载器，不改飞行或任务系统。夹具证明技术通路，不代表已制作完整空中城市和地下群系。

## M4 获取渠道与持久世界

目标：一个任务和一个商店完成装备进度闭环。

- [ ] 初始套机与组件永久免费使用，无续航或消耗机制。
- [ ] 终端或对接式中继任务，驱动设施灯光和闸门状态。
- [ ] 工业城市标签和任务完成事件共同满足一次装备授予条件。
- [ ] 修复授予轻型套机及必要组件、200 信用点。
- [ ] 商店以 150 信用点授予另一组 5 寸桨叶的永久使用权。
- [ ] 调试全解锁与普通进度隔离；未取得配件不能绕过检查。
- [ ] 保存世界版本、设施、任务、取得状态、信用点、事务和装配。
- [ ] 验证奖励重复触发、购买重复请求、退出恢复、写入失败和缺失内容处理。

验收：普通新档完整走通“起飞—任务—取得套机—商店—换件—重启恢复”，不会缺件、重复扣款或重复发奖。

## M5 P1 整合与交付

目标：交付能独立体验并供下一轮改进的完整原型。

- [ ] 一个路径移动主体和最小拍摄或截图功能。
- [ ] 操控、装备与交互提示清楚，默认探索无倒计时。
- [ ] 保存飞行问题复现所需的种子、机型、调参、输入设置和日志。
- [ ] 窗口环境下沿标准路线飞行 15 分钟，检查帧时间、内存、快速掉头与垂直移动。
- [ ] 安装匹配导出模板并导出 Windows x86_64，在编辑器外运行。
- [ ] 更新 README、文档、完成记录与已知限制，保留下一轮具体任务。

验收：以本机 1080p 简化画面稳定 60 fps 为目标，实测达不到时如实记录并先解决主要阻断。自动测试通过不能代替真实设备与用户试玩。

## P1 后续方向

1. 增加城市风格、自然群系、空岛与地下的正式内容，扩大连续探索范围。
2. 增加机型、配件、动力映射和城市获取渠道，保持旧进度迁移。
3. 完善拍摄任务、回放与作品分享，再扩展信号接力和可选巡逻。
4. 有测量依据后再考虑原生加速、复杂体素、联机及其他平台。

以上为候选路线，不在 P1 中同时实施。
