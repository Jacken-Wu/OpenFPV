# OpenFPV

<p align="center"><img src="game/assets/openfpv.svg" width="112" alt="OpenFPV 四旋翼图标"></p>

<p align="center"><a href="https://github.com/Jacken-Wu/OpenFPV">项目仓库</a> · <a href="https://github.com/Jacken-Wu/OpenFPV/releases">版本下载</a> · <a href="https://github.com/Jacken-Wu/OpenFPV/issues">问题反馈</a> · <a href="LICENSE">MIT 许可</a></p>

OpenFPV 是一款使用 Godot 4 和 GDScript 开发的穿越机自由探索游戏原型。驾驶四旋翼，在按种子生成的城市、山谷、浮岛和地下迷宫中探索，通过任务赚取信用点、购买配件，并调整属于自己的飞行手感。

自由探索优先：没有电池、续航、燃料或周期性补给。当前为 **世界版本 4 / 内容版本 0.22.0**，面向 Windows x64 发行。

- **开放世界：** 15 种群系，覆盖地表城市与荒野、空中浮岛、地下迷宫；探索可穿越的楼房、岩洞和巨构。
- **Acro 飞行：** 支持 USB 遥控器校准、逐通道死区、曲线与 PID 调节，也可使用键盘体验。
- **探索与挑战：** 穿门、气球、环绕、跟拍和区域解密；首次完成获得奖励，后续可重复练习。
- **自己的穿越机：** 用信用点购买套机和配件，自由组合兼容装备；操作预览便于录制飞行。

本文后续依次介绍[开始游玩](#开始游玩)、[操作与飞行](#操作与飞行)、[探索、地图与传送](#探索地图与传送)、[任务与奖励](#任务与奖励)、[商店、装备与调参](#商店装备与调参)、[源码构建](#从源码运行与构建)。

## 开始游玩

本节和后面的游玩指南面向 **Release 发行版**。发布版本后，在 [GitHub Releases](https://github.com/Jacken-Wu/OpenFPV/releases) 下载 Windows x64 的 `OpenFPV.exe`，双击即可游玩。游戏资源已经包含在 exe 中，不需要额外的 `.pck`、Godot 编辑器或启动脚本。

> **当前状态：继续测试，暂未发布可下载版本。** 仓库已建立，本次仅上传源码，不创建 tag 或 Release。上面的下载页会在首个版本发布后提供 exe；当前想从源码运行，请参阅本文最后的构建章节。

发行文件只有 `OpenFPV.exe`。游玩指南保留在仓库 README；项目与第三方许可证可在游戏中通过 **Esc → 关于与许可** 查看。开发者的源码运行、Debug 和 Release 构建方法见本文最后一节。

Windows 默认使用 Godot 的 Mobile 渲染器，在支持的设备上通过 Vulkan 绘制；无法使用时保留引擎自带的回退路径。这里的 Mobile 是渲染器名称，下载的仍是 Windows 桌面游戏。

推荐先完成下面的练习：

1. 连接 USB 遥控器，按 **F2** 选择输入设备并校准；没有遥控器时可用键盘体验。
2. 初次进入游戏处于暂停状态。先确认油门位置，再按 **P / 空格**恢复飞行；无需额外解锁电机。
3. 从低油门开始，练习起飞、减速和降落。需要重新开始时按 **R** 回到安全传送点。
4. 按 **M** 查看地图，选择附近任务，点击“领取并追踪”；也可以飞到任务接待平台停稳，按 **E** 接取。
5. 完成任务获得首次奖励，在已开放的服务平台停稳并按 **E** 购买或调整装备。

## 操作与飞行

### 常用按键

| 按键 | 功能 |
| --- | --- |
| P / 空格 | 暂停或恢复飞行 |
| E | 交互：接任务、登记平台、打开服务；部分终端需要持续按住 |
| R | 重置到安全传送点，并清零机体运动 |
| M | 打开或关闭探索地图 |
| F3 | 打开同一地图并优先查看附近任务，不自动切换当前追踪 |
| C | 切换第一人称与追逐视角 |
| F12 | 拍照；成功后显示照片路径，可复制或打开目录 |
| Esc | 暂停菜单，或返回/关闭当前页面 |
| F1 | 帮助与新世界入口 |
| F2 | 遥控器配置、校准与动作绑定 |
| / | 开发者控制台 |

地图使用滚轮缩放和拖动平移。再次按 M/F3 可关闭地图；菜单退出时恢复进入前的暂停状态。失去焦点或遥控器断开会触发暂停保护。

### 键盘体验

| 按键 | 飞行动作 |
| --- | --- |
| W / S | 俯仰 |
| A / D | 横滚 |
| J / L | 偏航 |
| ↑ / ↓ | 逐步增加 / 减少油门 |

键盘油门会保留当前值，松开方向键不代表自动回到零。键盘主要用于体验和调试，细腻操控建议使用遥控器。

游戏采用 **Acro 角速度控制**：摇杆控制机体的旋转速度，回中后停止主动旋转，但不会自动恢复水平。需要主动反打修正姿态。油门控制推力，机体倾斜后推力方向也会改变。

飞行高度超过 280 米时画面边缘会警示；超过 300 米时停止电机推力，下降至 280 米后解除保护。重力和惯性仍然存在，建议提前转向下降。

### USB 遥控器

F2 页面分别选择“遥控器配置”和“输入设备”。新建配置后，按页面提示移动四根轴采集行程，确认横滚、俯仰、偏航和油门的分配及正反方向，再保存使用。

- 每根姿态轴、油门和辅助轴可设置 **0～20% 死区**，用于抑制漂移和抖动。油门的死区作用在最低端。
- 辅助通道支持二档、三档、回弹、旋钮或按钮，可命名并绑定暂停、恢复、交互、重置、视角等动作。
- 已有配置可以编辑、改名和删除；新建或改名不能与其他配置重名。删除正在使用的配置后，需要重新选择输入。
- Esc →“操作预览”可以独立显示摇杆和拨杆状态，支持左右手油门布局，便于查看操作或录屏。

## 探索、地图与传送

世界包含城市、松林、峡谷、浮岛群、地下迷宫，以及高山、雪山、雪原、废城、巨构遗址、戈壁和火山等，共 15 个群系原型。每个独立地区有少量随机任务、服务平台和可穿越结构。

城市可探索楼间通道、工地、住宅、屋顶物件和广告架；戈壁有多轴镂空岩；山地、雪峰、深峡和火山区有弯曲主洞、回环、下探岔洞和交汇厅。巨构包含多层廊道、中庭和竖井。部分山地条件不适合生成洞穴时，不会强行挖洞。

地图保留已发现的地区，地下迷宫需要完成指定测绘任务后揭示内部结构。可切换高度层、定位无人机或查看全部已发现范围。

戈壁中的风蚀蜂窝岩属于可穿越的环境结构，不单独显示为特殊建筑图标；其他特色地点、任务和传送点仍可在地图查看。

**查看和追踪是两个动作：**

- 点击图标或任务列表只选中并查看详情；点击“追踪”才更换导航目标。
- 点击地图空白处只预览当前高度的临时路标，再点“追踪”才启用。连续查看新路标会保留原来的活动目标。
- 未接取的任务也可以先追踪接待平台，再飞过去接取；地图中的“领取并追踪”则直接登记任务。
- “清除指引”移除当前导航。停止追踪不会放弃已领取的任务。

**传送仅限已解锁的传送点。** 飞到平台中央降落、停稳后按 E 登记，再在地图详情中使用传送。任务图标、地标和临时路标不提供传送。传送后保持暂停，等待周边碰撞加载完成再恢复飞行。

失落废城的传送点和服务页面需要先完成当地 **3 条独立修复线路**。修复前在服务平台按 E 只显示要求；全部完成后开放当地网络。已经完成过的线路不会因重玩而重新锁定。

导航目标在实际视野内始终显示圆点/圆环，真正超出画面或位于身后时才显示边缘三角箭头。顶部信息栏不会把整片视野划成盲区；目标标记保留真实方位，说明文字自动避让面板。文字在当前方位仍无遮挡时保持该方位，避免随距离数字或细小转动反复上下跳动；下方箭头的说明贴在底部信息框上沿。

地下导航还会提前显示接下来几段细线和最多三个较淡的后续点，并提示随后转向或升降。最近目标最醒目，后续点不会盖住它；路线服从场景遮挡，避免把墙后的点误认成眼前的入口。

导航是飞行参考，不会自动驾驶。地表和空中指引不保证全局避障；地下导航按连通走廊及竖井规划。仍需观察建筑、地形和实际门框。

## 任务与奖励

每个地区通常有 **2～5 个公开任务**。任务平台旁的立体标签会随距离变小并被墙体遮挡：青绿表示未接取、金色表示已接取、蓝灰表示已完成，气球失败时显示红色。现场接取需要在小平台中央降落并停稳，悬停经过不会自动接取。

| 类型 | 完成方式 |
| --- | --- |
| 巡检 / 校准 / 维修 | 到目标处按提示持续交互或停留 |
| 快递 | 按提示领取并运送到目标位置 |
| 勘测 | 在指定地区完成测绘，部分任务用于揭示地下地图 |
| 摄影 | 满足画面中的距离、角度和遮挡要求后按 F12 |
| 立体穿门 | 按编号和箭头方向依次真正穿过各个门，无倒计时 |
| 扎气球 | 撞破陆续升空的全部气球，不能让任何一个超过限高 |
| 平面环绕 | 在要求的半径和高度内，镜头对准目标完成净 360° 环绕 |
| 跟拍 | 至少拍摄 30 秒，目标在视野中和在 50 米内的时间分别达到 80% |
| 区域解密 | 废城修复线路、巨构顺序终端或无碰撞穿行 |

### 立体穿门

已领取并追踪的穿门任务会绘制空间引导线：**金色是当前航段，青色是后续航段，沿线箭头表示前进方向**。通过一个门后，引导更新到下一段；已经完成的部分不再绘制。引导线遵守场景遮挡，菜单和拍照时隐藏。

门位可能靠近楼层、屋顶、立面或竖井，包含近距转向、上下叠门、升降变线及较大的门面方向变化，并与较长航段混合。线条仅供参考，完成仍以按正确方向穿过实体开口为准。中间门有短提示音，终点使用另一种提示音。

### 气球与运镜

地图远程接取气球任务后不会马上放球，需要到接待平台停稳按 E 启动。现场首次接取会直接开始准备，约 3 秒后逐只放出。气球持续上升，任一越过提示限高则失败，返回平台可重试；爆破有音效和彩纸。暂停会停止计时，换追踪不会停止已启动的气球。

环绕时失去取景或短暂偏离只暂停累计，回到范围可继续；反向环绕会抵消净进度。跟拍的两项 80% 分别统计，失误后可以延长拍摄追回比例；实际视野和墙体遮挡会影响判定。以右上角当前任务提示为准。

### 区域任务与重玩

废城修复终端需要靠近、低速并按住 E。巨构顺序终端需要按提示顺序激活；无碰撞穿行需要在不接触墙壁、障碍物或地面的情况下完成路线，碰撞或重置会重开本次挑战，没有倒计时。

任务可以再次接取，**只有第一次完成发信用点或装备**。任务阶段和首次奖励记录随世界存档保存；新版布局保留已接旧任务的原路线，新旧布局共享首次奖励。

地图可筛选未完成、进行中和已完成任务。列表与图标统一使用金色、绿色和蓝灰色区分，重玩不抹去曾完成记录。

## 商店、装备与调参

在已开放的服务平台中央停稳，按 E 打开综合服务。商店按完整套机、机架、电机和桨叶分类，购买的配件永久拥有。当前共有 14 件商品，包括花飞 5、远景 6、影航 3.5 等套机及对应配件。

装备需要满足机架孔位、电机轴孔、桨径等兼容条件；当前保持四个同型号电机和四片匹配桨叶。参数调整保存在自己的存档里，不修改共享配件定义。

服务页面的“操控曲线”可逐轴调整最大角速度和 Expo，下方可调整 **P / I / D 与 D 滤波**。P 影响跟随力度，I 修正持续偏差，D 提供回杆阻尼。建议从默认值小幅调整，保存后试飞；恢复默认 PID 不会清掉自己的角速度曲线。

“高级环境”还可调整重力、空气阻力和转动阻力。修改后需要“保存并应用”；取消不改变已保存设置。再次按 E 可保存并退出服务页面，保存失败时页面会保留。

## 菜单、声音、成就与存档

- **声音设置：** 选择输出设备，分别调节主音量、音效、电机、快门和背景音乐；实时预览，保存生效，取消撤销。设备缺失时临时使用系统默认。15 个群系有各自的原创 8bit 风格背景曲，切换时渐变衔接。
- **探索成就：** Esc 中查看群系、传送点和任务类型等收藏进度，仅用于探索记录，没有额外奖励。
- **关于与许可：** Esc 中查看项目 MIT、Godot 及第三方组件的完整许可声明，内容内嵌在程序中。
- **多个存档：** 在存档管理中保存、复制、改名、加载或回收世界，不同世界可使用不同种子。删除的非活动存档移入回收区；遥控器等玩家操控设置可以跨世界沿用。
- **照片：** F12 保存截图并显示实际路径。普通照片和满足条件的任务照片都可以保留；拍摄证据与奖励必须成功保存后才算完成任务。

同一构建渠道内，当前 v4 存档的装备、余额、探索和任务记录会继续保留。Debug 与 Release 的存档、遥控器设置、照片和回收区完全分开，发行版不会自动导入开发数据；Release 首次运行需设置自己的遥控器。很早的 v1/v2/v3 世界会重建新版世界进度并保留操控设置；操作前请阅读页面提示。

当前仍是原型。首次加载远处地区可能出现停顿；不同显卡和窗口比例下的画面、真实遥控器手感与任务难度仍在持续验证。已完成的自动验证和具体限制见[验证记录](docs/VALIDATION.md)。

## 反馈问题

当前仍在测试中。遇到问题时，可以在 [Issues](https://github.com/Jacken-Wu/OpenFPV/issues) 中描述复现步骤，并尽量提供：

- 游戏版本及使用的 Debug / Release 渠道。
- 世界种子、左侧显示的世界坐标，以及附近传送点或任务名称。
- 问题出现前的操作；重新启动或重新进入地区后是否仍会出现。
- 画面问题的截图或短录屏，保留坐标与状态信息；同时注明显卡和窗口模式。

需要提供存档时，先备份，再选择发生问题的世界存档；无需上传个人遥控器配置或整个用户数据目录。保存位置见最后一节的渠道数据说明。

## 开发者定位工具

按 `/` 打开控制台，输入 `/help` 查看指令。例如：

```text
/location list
/location snow_peak
/tp location
/pos
/seed
```

`/location` 查找指定群系或区域，`/tp location` 调试传送到上次定位的平台。定位本身不会提前解锁地图；调试传送不替代已保存的安全起降点。普通地图传送仍遵守平台解锁条件。

## 从源码运行与构建

源码仓库为 [Jacken-Wu/OpenFPV](https://github.com/Jacken-Wu/OpenFPV)。以下操作面向开发者，在克隆后的项目根目录执行：

```powershell
git clone https://github.com/Jacken-Wu/OpenFPV.git
cd OpenFPV
```

### 环境与导出模板

- 使用 **Godot 4.7.2 Standard** 与 GDScript，无需 Godot .NET 版本或额外安装编译工具链。
- 当前自动化构建面向 Windows x64，使用 PowerShell。脚本严格检查引擎版本。
- 原生 Debug 和 Release 导出都需要匹配版本的 Windows x64 导出模板，不再把编辑器程序复制成游戏运行程序。
- 游戏运行和构建无需 Python；只有重新生成原创音乐时才需要 Python 3，并运行 `python tools/ComposeMusic.py`。

在仓库根目录指定自己的 Godot 控制台程序：

```powershell
$env:GODOT_EXE = 'D:/Tools/Godot/Godot_v4.7.2-stable_win64_console.exe'
& $env:GODOT_EXE --version
```

各脚本也接受 `-GodotPath '你的Godot控制台程序路径'`。或者将绝对路径写入本机 `.local/godot-path.txt`；该文件不提交到仓库。

首次准备模板可以选择以下一种方式：

```powershell
# 已在Godot模板管理器安装4.7.2：导入本机模板
./tools/Setup-ExportTemplates.ps1

# 使用已经下载的官方Standard模板归档
./tools/Setup-ExportTemplates.ps1 -Archive 'D:/Downloads/Godot_v4.7.2-stable_export_templates.tpz'

# 或由脚本下载官方模板（归档约1.28GB）
./tools/Setup-ExportTemplates.ps1 -Download
```

模板来自 [Godot 4.7.2 官方下载归档](https://godotengine.org/download/archive/4.7.2-stable/)。脚本检查版本，仅将 Windows x64 Debug/Release 模板提取到项目 `.local/export-templates/4.7.2.stable/`。模板属于本机缓存，不进入源码或发行包；构建本身不会静默下载。

项目使用原创四旋翼图标。模板准备脚本同时调用 `Prepare-ExportIcon.ps1`，通过 Windows 自带资源接口给模板的私有副本写入 16～256 像素共七种图标，随后由 Godot 导出游戏资源。它不修改已内嵌 PCK 的成品，不需要安装 rcedit；`tools/windows_icon.cs` 仅供 PowerShell 构建时使用，不进入游戏，也不要求 Godot .NET。

图标源稿为 `game/assets/openfpv.svg`。修改源稿后，可在仓库根目录重新生成 PNG 预览与 ICO：

```powershell
& $env:GODOT_EXE --headless --path game --script "$PWD/tools/render_icon.gd"
```

### 源码运行与 Debug 构建

编辑器或源码运行属于 Debug 渠道，不需要先导出模板：

```powershell
./tools/Run.ps1 -Editor
./tools/Run.ps1
```

也可在 Godot 项目管理器导入 `game/project.godot`，按 F5 运行项目，或运行主场景 `game/scenes/main.tscn`。

生成真正的 Debug 导出：

```powershell
./tools/Build.ps1 -Configuration Debug
```

输出在 `builds/Debug/`，包含 `OpenFPV.exe` 和外置 `OpenFPV.pck`。Debug 窗口带有 `[Debug]` 标记，用于本地开发验证，**不放 README、开源协议或发行文档，不用于发布**。省略 `-Configuration` 时也默认构建 Debug。

### Release 发行构建

```powershell
./tools/Build.ps1 -Configuration Release
```

输出目录 `builds/Release/` **只包含 `OpenFPV.exe`**，可作为 GitHub Release 的附件上传。README、LICENSE 和发行文档均不复制到该目录；旧构建留下的这些文件会由脚本清理。游戏资源和完整许可声明内嵌到 exe，无需外置 `.pck`、编辑器或调试模板。

构建会实际运行导出的 exe，确认 Release/Debug 模式、数据目录与模板身份，检查内嵌许可，再执行冒烟检查并对照源码内容指纹。源码仓库保留 README、LICENSE 和开发文档。

Godot 导出预设分别是 `Windows Debug` 和 `Windows Release`，Release 预设启用 PCK 内嵌。推荐使用构建脚本，它会先同步 `game/legal/` 中的版权与引擎声明，再导出程序。手动导出前也需确保这两份许可资源为最新内容，并使用与所选模式对应的原生模板。

### 两个渠道的数据隔离

在 Windows 上，数据目录为：

| 渠道 | 用户数据目录 |
| --- | --- |
| 源码 / Debug | `%APPDATA%/Godot/app_userdata/OpenFPV · 重连边境`，继续使用已有开发数据 |
| Release | `%APPDATA%/OpenFPV/Release`，独立的正式游玩数据 |

存档、设置、遥控器配置、照片、备份和回收区全部位于各自目录内。两个渠道不自动读取、复制或合并彼此的数据。Release 更新程序后继续读取自己的目录，不依赖 exe 被放在哪个文件夹。

### 检查与验证

```powershell
# 导入、逻辑测试和源码冒烟检查
./tools/Test.ps1

# 加上正常窗口与场景检查
./tools/Test.ps1 -Window

# 分别构建Debug/Release，并验证数据隔离和单exe运行
./tools/Test-Distribution.ps1

# 两个版本已经构建完成时，可跳过重复构建
./tools/Test-Distribution.ps1 -SkipBuild

# 最大化窗口进行60秒连续跨区测量（独立运行，避免同时进行其他检查）
./tools/Bench-Streaming.ps1 -Seconds 60

# 附件黑闪位置的第一人称逐帧诊断（完整HUD，隔离测试档）
& $env:GODOT_EXE --path game --script res://tests/city_render_tests.gd -- --test-session
```

测试使用隔离存档，日志和截图在 `.local/test-results/`。分发检查分别启动两个真实程序，检查存档/照片各自持久化、互不串用，并将 Release exe 单独复制到新目录运行。无窗口检查不能代替画面、声音与遥控器手感验证。

开发排查时可在 Godot 命令后加 `--rendering-method gl_compatibility`，与旧 OpenGL 路径对照；不需要改存档。逐帧诊断会读取 GPU 图像并影响帧时间，不能把它的“未捕获黑闪”当作所有设备、实际录屏与持续飞行都已根治。

项目保留 `editor/export/convert_text_resources_to_binary=false`，用于避免已记录的资源转换兼容问题。修改该设置后需要重新验证源工程和两类导出。`builds/`、`.local/`、`.code/`、导入缓存、个人照片和测试存档均不提交到源码仓库。
